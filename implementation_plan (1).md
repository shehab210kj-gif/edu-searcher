# Implementation Plan - Previews, Exports, and Formatting Refinement (v2 - Updated)

This plan addresses all reported preview, export, formatting, and feature enhancement requests, with additional reliability, performance, and security refinements.

## User Review Required

> [!IMPORTANT]
> - **Nixpacks Chromium Requirement**: Headless PDF generation depends on Chromium. We will install Chromium via a new `nixpacks.json` file on the server, with explicit executable path and sandbox configuration for container environments.
> - **References Clean-up**: We will automatically filter out sections generated by AI that are named "المراجع" or "References" (and normalized variants) to prevent duplicate lists, rendering only the structured academic bibliography.
> - **University Name Mapping**: Saudi university name translation will use a static mapping table first, falling back to dynamic translation only for unrecognized names, to avoid inaccurate translations of official institution names.

## Proposed Changes

### 1. Nixpacks Build Configuration

#### [NEW] [nixpacks.json](file:///c:/Users/CityLap/Downloads/Salaam-Alaikum/nixpacks.json)
- Define a custom setup phase to install `chromium` via apt packages, ensuring Puppeteer can launch on Railway for PDF exports.
- Set `PUPPETEER_EXECUTABLE_PATH` env variable pointing to the installed Chromium binary, so Puppeteer doesn't attempt to re-download its own bundled Chromium.
- Add required launch args in the Puppeteer client config: `--no-sandbox`, `--disable-setuid-sandbox`, `--disable-dev-shm-usage` (containers often have limited `/dev/shm`), since Railway containers typically run without full sandbox privileges.
- Implement a browser instance pool/singleton (e.g., keep one long-lived Chromium instance and open new pages/tabs per request) instead of launching a fresh browser process per PDF request, to reduce latency and resource usage under concurrent load.

### 2. Database Schema and Library Preview

#### [MODIFY] [library.ts (API Routes)](file:///c:/Users/CityLap/Downloads/Salaam-Alaikum/artifacts/api-server/src/routes/library.ts)
- Modify the `/api/library/:id/preview.pdf` route.
- If `originalFileUrl` is absent (pre-seeded templates), construct a PDF dynamically from `richContent` using `buildPdfFromRich` so the preview works seamlessly instead of returning 404.
- If `richContent` is also missing/empty, return a clear, user-friendly error response (e.g., 422 with a descriptive message) instead of crashing or returning a generic 500.
- Add caching for generated previews (keyed by content hash or `updatedAt` timestamp) so repeated preview requests don't rebuild the PDF unless the underlying content changed.
- Sanitize any HTML/user-or-AI-generated content in `richContent` before rendering it in headless Chromium, to prevent SSRF or local-resource-access risks (e.g., external `<img>`/`<iframe>` sources reaching internal services).

### 3. Exporter Refinement (Word & PDF)

#### [MODIFY] [format-pipeline.ts](file:///c:/Users/CityLap/Downloads/Salaam-Alaikum/artifacts/api-server/src/lib/format-pipeline.ts)
- Update `buildFormattedDocument` to identify and skip any sections with headings matching "المراجع", "References", "قائمة المراجع", "المصادر", etc.
- Normalize heading text before comparison: trim whitespace, strip punctuation/numbering prefixes (e.g., "6. المراجع"), and perform case-insensitive matching.
- Restrict the match/skip logic to actual heading elements (H1/H2 level), not arbitrary paragraphs that happen to contain these words, to avoid accidentally removing legitimate content.
- This ensures references are only printed once through the structured bibliography.

#### [MODIFY] [rich-export.ts](file:///c:/Users/CityLap/Downloads/Salaam-Alaikum/artifacts/api-server/src/lib/rich-export.ts)
- Update `coverHtml` to use a 3-column clean HTML table for the header (Arabic text right-aligned, logo centered, English text left-aligned).
- Center and format the remaining cover metadata (student name, supervisor, degree, year) beautifully.
- Maintain a static mapping table of standard Saudi university names (Arabic → English, e.g., "جامعة الملك سعود" → "King Saud University") for accurate, consistent translation.
- Fall back to dynamic (AI-based) translation only when a university name isn't found in the static mapping table.

### 5. Reliability & Operations (New)

- **Error handling / retry logic**: Wrap Puppeteer PDF generation calls with retry logic (e.g., 1-2 retries with backoff) to handle transient failures such as the Chromium process hanging or closing unexpectedly. Ensure failures return clear API error messages rather than silent timeouts.
- **Process health checks**: Periodically verify the pooled browser instance is still responsive; relaunch it automatically if it has crashed or become unresponsive.
- **Load testing**: Before/after deploying to Railway, run load tests simulating concurrent export/preview requests to validate that the Chromium pooling setup and container resources (CPU/memory) can handle expected usage at scale.
